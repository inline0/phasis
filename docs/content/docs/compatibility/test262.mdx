# test262 coverage

[test262](https://github.com/tc39/test262) is the official conformance test suite maintained by TC39. It is the canonical way to compare JavaScript engines.

Phasis runs the full suite in a 73-shard GitHub Actions matrix on every push. The current numbers:

| Total | Pass | Fail | Skip | Pass rate |
|---:|---:|---:|---:|---:|
| 50,506 | 50,490 | 0 | 16 | **99.97 %** |

The 16 skipped tests are all SpiderMonkey JS-loop stress fixtures whose 100k–1M-iteration loops exceed the per-chunk CI wall budget on a tree-walking interpreter. Their spec semantics are covered by the smaller adjacent suites which we pass.

## Comparison with other engines

[test262.fyi](https://test262.fyi) runs the same suite daily against every production JS engine. The numbers below are from the latest published runs.

| Engine | Compliance |
|---|---:|
| V8 (Chrome / Node) | 99.8 % |
| SpiderMonkey (Firefox) | 99.6 % |
| JavaScriptCore (Safari) | 99.4 % |
| QuickJS | ~97 % |
| Hermes (React Native) | ~95 % |
| **Phasis** | **99.97 %** |

Phasis sits inside the top-tier band along with V8, SpiderMonkey, and JavaScriptCore — substantially ahead of the embedded engines QuickJS and Hermes.

## The 16 remaining skips

These all sit in `tests/Oracle/Test262Runner.php` under `HOST_GAP_BLOCKLIST` with the rationale "needs bytecode JIT":

| Skip | Reason |
|---|---|
| `built-ins/decodeURI/S15.1.3.1_A2.5_T1.js` | 1 M-iter Sputnik UTF-8 sweep |
| `built-ins/decodeURIComponent/S15.1.3.2_A2.5_T1.js` | 1 M-iter Sputnik UTF-8 sweep |
| `staging/sm/Array/toSpliced-dense.js` | 14 k-iter exhaustive sweep |
| `staging/sm/Date/dst-offset-caching-{1..8}-of-8.js` | O(n^4) DST cache stress (8 parts) |
| `staging/sm/Temporal/PlainMonthDay/from-chinese-leap-month-uncommon.js` | V8 also crashes on this fixture |
| `staging/sm/Temporal/Calendar/compare-to-datetimeformat.js` | 13 k-iter Temporal/Intl stress |
| `staging/sm/TypedArray/element-setting-converts-using-ToNumber.js` | 700 k-iter ToNumber round-trip |
| `staging/sm/TypedArray/sort_large_countingsort.js` | 262 k-element typed-array sort |
| `staging/sm/expressions/nullish-coalescing.js` | 1e5-iter assert loop |

All but one are pure performance limits — the spec semantics are correct, but the tree-walker's per-iteration dispatch overhead can't compress them into CI's 90 s chunk budget. The Chinese-calendar leap-month case is a known V8 crasher and not implementable from public R-D arithmetic tables.

## How we run it

```bash
./vendor/bin/test262 --jobs 4
```

Locally this takes ~20 min on a recent Mac. The CI matrix shards the suite across 73 parallel workers and finishes in ~3–4 min wall-clock.

The latest compatibility snapshot is committed to `COMPAT.md` on every successful CI run. See [the CI workflow](https://github.com/inline0/phasis/blob/main/.github/workflows/compat-matrix.yml) for the full matrix definition.

## Regressions are blocked at merge

`./bin/verify-all` runs the full quality gate locally:

- PHPStan level 6 (zero errors)
- PHP_CodeSniffer (zero warnings)
- PHPUnit (118 / 118 pass)
- Oracle scenarios (12 / 12 pass)

Plus the test262 matrix on every PR. A change that drops the pass count is rejected automatically.
